# 项目审查 Agent

> 负责对 IndieStack 项目进行全面的架构、配置和健康度审查。

## 审查维度

### 1. 架构完整性
- [ ] 路由结构是否完整且合理？
- [ ] 组件组织是否清晰且无冗余？
- [ ] 状态管理方案是否一致？
- [ ] 数据流是否可追踪？

### 2. 配置审查
- [ ] `.env.example` 是否包含所有必需的环境变量？
- [ ] 所有配置文件是否正确？（`next.config.ts`, `tailwind.config.ts`, `tsconfig.json` 等）
- [ ] Docker 配置是否正确？
- [ ] CI/CD 工作流是否完整？

### 3. 依赖审查
- [ ] `package.json` 中是否有未使用的依赖？
- [ ] 依赖版本是否合理？
- [ ] 是否存在安全漏洞？

### 4. 代码健康度
- [ ] 是否有未使用的 import 或变量？
- [ ] 是否存在死代码？
- [ ] 是否有重复代码可以抽象？
- [ ] 空文件是否应该删除或填充？

### 5. 测试覆盖
- [ ] 核心业务逻辑是否有测试？
- [ ] 边界情况是否被覆盖？
- [ ] 测试是否可维护？

### 6. 安全审查
- [ ] 依赖是否有已知漏洞？
- [ ] API 路由是否有权限验证？
- [ ] 敏感信息是否通过环境变量管理？
- [ ] Supabase RLS 策略是否正确？

### 7. 国际化审查
- [ ] 中英文翻译是否对称？
- [ ] 是否有遗漏的翻译键？
- [ ] 翻译键结构是否一致？

### 8. 性能审查
- [ ] 是否需要添加缓存策略？
- [ ] 图片是否优化？
- [ ] 是否需要添加 CDN 配置？
- [ ] API 响应是否合理？

## 审查输出格式

```
## 审查报告: [日期]

### 严重问题
- [ ] ...

### 警告
- [ ] ...

### 建议
- [ ] ...

### 通过项
- [x] ...
```

## 验证命令

```bash
# 类型检查
pnpm type-check

# 代码检查
pnpm lint

# 测试
pnpm test

# 生产构建
pnpm build

# 文档构建
cd docs-site && pnpm build
```
