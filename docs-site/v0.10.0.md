# v0.10.0 (2026-09-13)

v0.10.0 consolidates the interface layer into a reusable system. Instead of every
page hand-writing its own labels, colour scales, skeletons and empty states, the
UI now has a single place to change each of those — and a gate that fails the
build when a page drifts back to the old pattern.

There are **no database migrations** in this release. It is a pure
application-layer change.

## Highlights

- **Tailwind v4 native theming**: the two hand-rolled animations (indeterminate
  progress bar and route-change bar) moved from bare `@keyframes` +
  `@layer utilities` into `@theme` tokens
  (`--animate-progress-indeterminate` / `--animate-navprogress`) with the
  keyframes inlined in the same block, so usage is back to plain `animate-*`
  utilities. Dead `.step` / `.step:before` CSS was deleted, and the pilot page
  plus shared forms were upgraded from v3 spellings (`bg-gradient-to-b` →
  `bg-linear-to-b`, `outline-none` → `outline-hidden`).
- **Design token registry**: `src/lib/design/tokens.ts` registers 39 tokens
  (including `--success` / `--warning` / `--info`, each with a foreground).
  Eleven business files moved off raw Tailwind palettes (`bg-green-500`,
  `text-amber-600`, `bg-red-500`, …) onto semantic utilities, gaining a real
  dark-mode fallback for the first time. `--color-chart-1..5` also gained its
  missing `@theme` mappings — `text-chart-N` / `fill-chart-N` did not actually
  exist before.
- **Shared form field primitive**: `src/components/shared/form-field.tsx` wires
  label, control, description and error through one context that injects
  `htmlFor` / `id`, merges `aria-describedby` and sets `aria-invalid="true"` on
  error, with stable ids per description and error. Native dropdowns folded into
  `native-select.tsx`, and 15+ forms migrated.
- **Shared loading / empty / error states**: `PageLoading`
  (`cards` / `dashboard` / `stats` / `list` / `spinner`) and `LoadingIndicator`
  are the single source for loading, `EmptyState` for empty, and the new
  `ErrorState` for errors. Containers carry `aria-busy="true"` and a
  `role="status"` screen-reader announce through next-intl — three route
  skeletons previously had no `aria-busy` at all and had hardcoded Chinese copy.
  Ten bare empty-state paragraphs and four error boundaries migrated, and the two
  unreferenced duplicate loaders (`page-loader.tsx`, `loading-state.tsx`) were
  deleted.
- **Dark mode first-paint fix**: the root layout injects a CSP-nonce'd blocking
  script that writes the `<html>` class and `color-scheme` before CSS parses, so
  dark-theme users no longer see a flash of light. The storage-key mismatch that
  silently dropped the preference on reload (provider wrote `ui-theme`, other
  call sites read `theme`) is fixed by moving the key and parse rules into
  `src/lib/theme/theme.ts`.
- **Mobile breakpoint regressions**: a new `e2e/responsive.spec.ts` at 375 / 768
  / 1280 exposed two real defects — the container's fixed 2rem padding pushed
  content past a 375px viewport (`scrollWidth` 428 > 375), and the dashboard
  sidebar's `hidden md:block` made navigation unreachable on phones. Container
  padding is now 1rem on phones / 2rem at ≥640px, and `MobileDashboardNav`
  (ui/sheet drawer, closes on navigate) restores reachability.
- **Keyboard and screen reader fixes**: a role/accessible-name based
  `e2e/keyboard.spec.ts` exposed four gaps — skip-link targets were not
  focusable, the mobile menu ignored `Esc` and dropped focus, the collapsed
  sidebar toggle had no accessible name or state, and the `?` shortcut fired
  inside contenteditable / `role="textbox"` and on modified combinations.
- **Four new UI gates**: `pnpm check:tailwind`, `check:tokens`, `check:fields`
  and `check:states` turn each of the above conventions into an executable rule
  set (7 / 8 / 3 / 4 rule codes), all wired into `pnpm check:all` and CI.

## Upgrade Notes

1. No migrations and no environment-variable changes. Deploy order is
   unconstrained.
2. The removed `page-loader.tsx` / `loading-state.tsx` had zero references. If a
   downstream branch still imports them the build fails immediately rather than
   regressing silently.
3. `globals.css` is now the only place where status colours and animation tokens
   are defined. Change the `:root` / `.dark` variables, not the utility classes
   in call sites — `pnpm check:tokens` enforces this.
4. Run `pnpm check:all` before pushing: the four new gates are part of it.

## Known Limitations

The state and form-field gates are static writing audits, not semantic analysis.
They catch raw `<select>`, copied control class strings, `animate-spin` outside
the allowlist and `text-center` + fixed vertical padding placeholders; they do
not prove correct runtime ARIA behaviour, which the primitive unit tests cover.
Visual regression still only covers four public pages (home / features / pricing
/ login) at 1440×900.
