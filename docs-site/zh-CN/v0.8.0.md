# v0.8.0（2026-09-13）

v0.8.0 把 Web Push 从即时 best-effort 投递升级为带重试队列与死信可见性的持久化、at-least-once 通道。

## 亮点

- **持久化投递队列**：新增 `026_push_delivery_attempts.sql`，按 `(notification_id, endpoint)` 每行记录
  `pending` / `sent` / `dead` 状态、尝试次数、失败原因与 `next_attempt_at`。唯一键加幂等入队保证重试不会
  重复推送给已成功的端点，单个端点失败也不会再扇出影响其他端点。
- **指数退避与重试上限**：瞬时失败按 60 秒、120 秒（`60s × 2^(n-1)`，上限 1 小时）重试，
  最多 3 次（含首次），超出后进入死信状态。
- **失效端点处理**：push service 返回 `404`/`410` 时立即撤销本地订阅并将该行转入死信，不再重试。
- **重试 worker**：`/api/cron/push-retry` 每 15 分钟运行一次（单轮 50 条），受 `CRON_SECRET` 保护，
  仅返回脱敏计数。VAPID 未配置时整轮快速失败，而不是静默把队列转成死信。
  > 该调度已于 2026-09-21 改为每天 22:00 UTC 一次（`0 22 * * *`）：Vercel Hobby 每个路径每天最多
  > 运行一次，`*/15 * * * *` 如今会被平台拒绝部署。现行调度见《Web Push》文档。
- **有界队列保留**：每轮 worker 清理超过 7 天的 `sent` 与超过 30 天的 `dead`，单一状态最多 1000 行；
  `pending` 永不清理，响应以 `pruned` 返回删除计数。
- **可观测性**：新增 `push.backlog`（告警阈值 500）、`push.delivery.dead`、`push.endpoint.revoked`、
  `push.queue.pruned|prune_failed` 与 `cron.push-retry.completed|failed` 指标。

## 升级说明

1. 应用迁移 `026_push_delivery_attempts.sql`——它是纯新增，不修改任何既有表；已基线化的迁移保持 SHA-256 固定。
2. 确保部署环境存在 `CRON_SECRET`：新的 cron 路由（以及既有 digest/restore 路由）在缺失时返回 `401`。
3. 浏览器推送仍需 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`、服务端专用的 `VAPID_PRIVATE_KEY` 与 HTTPS 生产域名。
4. 投递语义现在是 **at-least-once**。极端情况下（回执写入前进程崩溃）同一端点可能收到两次通知；
   站内通知仍是唯一事实来源，客户端应保持按 `idempotencyKey` 幂等。

## 已知限制

重试与死信链路已由单测与本地数据库 smoke 覆盖，但尚未有端到端浏览器用例——该任务安排在下一里程碑。
生产环境请用真实 `CRON_SECRET` 触发一次 `/api/cron/push-retry` 验证队列。
