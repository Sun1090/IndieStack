# v0.7.0（2026-09-12）

v0.7.0 把 Web Push 从占位实现变为真实投递通道，并加固迁移、依赖与 secrets 相关的仓库门禁。

## 亮点

- **Web Push 真实投递**：使用 `web-push` 与 VAPID 鉴权，固定 1 小时 TTL、10 秒超时和 high urgency。
  投递会扇出到该用户的全部订阅，并立即撤销 push service 返回 `404`/`410` 的失效端点。
  Push 失败不会抑制站内通知或邮件。
- **设置页订阅生命周期**：`/dashboard/settings` 刷新后可识别既有浏览器订阅并支持关闭，同时撤销数据库
  记录与浏览器订阅。
- **迁移漂移门禁**：`pnpm check:migrations` 现在校验迁移命名、编号、编码以及每个迁移与提交清单比对的
  SHA-256；已基线化的迁移不可改写。
- **依赖与 secrets 门禁**：`pnpm check:security` 对高危/严重漏洞、被跟踪的环境与私钥文件、过宽的文件
  权限、客户端服务端变量泄漏以及 workflow 权限漂移全部 fail-closed。
- **运维文档**：新增中英双语的 Web Push、邮件投递与文件存储章节。

## 升级说明

1. 本版本没有新增迁移，最新仍为 `025_notifications_realtime.sql`；部署前先应用所有待执行迁移。
2. 如需开启浏览器推送，请设置 `NEXT_PUBLIC_VAPID_PUBLIC_KEY` 与服务端专用的 `VAPID_PRIVATE_KEY`
   （用 `pnpm exec web-push generate-vapid-keys` 生成一次即可）。缺任一密钥时 provider 保持未配置，
   设置页显示“未配置”，也不会写入订阅。
3. 生产环境必须使用 HTTPS：除 localhost 外，浏览器只在安全上下文中暴露 Service Worker 与 PushManager。
   `NEXT_PUBLIC_APP_URL` 非 HTTPS 时，适配器回退到 `mailto:support@indiestack.dev` 作为 VAPID 主体。

## 已知限制

Push 为即时 best-effort 投递，目前没有持久化重试队列或死信表：瞬时失败只记录日志与
`push.send.failed{reason}` 指标，站内通知始终是事实来源。持久化重试计划在下一里程碑实现。
