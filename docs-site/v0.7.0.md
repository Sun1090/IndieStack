# v0.7.0 (2026-09-12)

v0.7.0 turns the Web Push placeholder into a real delivery channel and hardens
the repository gates around migrations, dependencies and secrets.

## Highlights

- **Web Push delivery**: `web-push` with VAPID authentication, a 1-hour TTL, a
  10-second timeout and high urgency. Delivery fans out to every subscription of
  a user and revokes endpoints the push service reports as permanently gone
  (`404`/`410`). Push failure never suppresses the in-app notification or email.
- **Settings lifecycle**: `/dashboard/settings` detects an existing browser
  subscription after a reload and can disable it, revoking both the database row
  and the browser subscription.
- **Migration drift gate**: `pnpm check:migrations` now validates naming,
  numbering, encoding and the SHA-256 of every migration against a committed
  manifest; already-baselined migrations cannot be rewritten.
- **Dependency and secrets gate**: `pnpm check:security` fails closed on
  high/critical advisories, tracked environment/private-key files, overly
  permissive env file modes, client-side server-variable leaks and workflow
  permission drift.
- **Operations docs**: new Web Push, email delivery and file storage chapters in
  both languages.

## Upgrade Notes

1. No new migrations in this version; the latest remains
   `025_notifications_realtime.sql`. Apply anything pending before deploying.
2. To enable browser push, set `NEXT_PUBLIC_VAPID_PUBLIC_KEY` and the
   server-only `VAPID_PRIVATE_KEY` (generate them once with
   `pnpm exec web-push generate-vapid-keys`). Without both keys the provider
   stays unconfigured, the settings page reports “not configured” and no
   subscription is stored.
3. Production must run on HTTPS: browsers only expose Service Worker and
   PushManager in a secure context (localhost is the development exception).
   When `NEXT_PUBLIC_APP_URL` is not HTTPS the adapter falls back to
   `mailto:support@indiestack.dev` as the VAPID subject.

## Known Limitations

Push is immediate and best-effort. There is no durable retry queue or
dead-letter table yet: transient failures are logged with a
`push.send.failed{reason}` metric, and the in-app notification remains the
source of truth. A durable retry path is planned for the next milestone.
